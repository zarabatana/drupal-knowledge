Continuously maintained, evidence-backed Drupal knowledge — where every claim says where it came from and how far it can be trusted.

What it is

Drupal Knowledge reads official Drupal sources — the security advisories, the API deprecation index, core change records, Drupal.org documentation — and keeps what they say as records you can trace back to the exact bytes they were derived from. A smaller set of records has been reviewed by a human and states something about Drupal in its own right.

Those two things are not the same, and the difference is visible on every page. An advisory is authoritative about Drupal without being a Drupal Knowledge rule. A case solved on one site is not a universal requirement. Nothing here quietly becomes knowledge because it was popular or recent.

What it does not claim

  • It is not comprehensive. It holds what has been acquired and reviewed, and it says how much that is.
  • It does not manufacture severity. Where a source published a risk vector, that vector is shown; no score is computed from it.
  • It does not tell you a site is secure. Finding nothing within a bounded scope is not a clean bill of health.
  • It is not generated by a language model. Records are projected from sources deterministically, and the review step is a person.

How to use it

Search for an advisory ID, a CVE, a deprecated function or a module name. Or browse a domain below — each one tells you up front what kind of claim its records make.

To ask about your own Drupal project, use the command line. It reads your repository and changes nothing: 

git clone https://github.com/zarabatana/drupal-knowledge.git
cd drupal-knowledge
./dk project /path/to/your-drupal-project

The full CLI guide covers upgrades, migration work and provenance.
