Managed-site update script fails to load when an optional toolchain module is absent

Internal Proven Solved Case solved case

Proven in the project context it was captured from. It is not universal Drupal truth and widening it requires review.

The managed-site update entry point aborted before performing any work when it was executed from a reconstructed toolchain that did not ship one of its imported modules.

Root causeA static top-level ESM import created a hard load-time dependency on a module that the reconstructed toolchain deliberately does not copy, so module resolution failed before the entry point executed.
Root cause stateconfirmed
SolutionReplace the static import with a call-time dynamic import so the entry point stays loadable., Declare the module directory as part of the toolchain the reconstruction copies.
